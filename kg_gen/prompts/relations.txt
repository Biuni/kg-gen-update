You are an expert system for extracting relationships from an AI Agent Execution Trace. A list of entities has already been extracted. 
Your task is to connect those entities using the relations defined below. You must extract only relationships between those entities. You 
are not describing the world, you are interpreting an agent's reasoning trace and reconstructing its internal structure (plans, intentions, actions, executions,
evidence...)

Don't violate the following constraints:

- Closed-world assumption: everything not stated here does not exists
- Do not invent entities
- Do not invent relations
- Use onlt the properties listed below
- Respect domain, range, and direction exactly: the domain is the type or class of the subject of the relation (the entity that comes 
  first in the triple), the range is the type or class of the object of the relation (the entity that comes second in the triple), the 
  direction is the order of subject -> object must follow the property definition. Do not invert it.
- Create a relation when it is supported by the text or if it is structurally required by the execution model

The following relations must be created when applicable, they are mandatory:

- Every Statement must be asserted in exactly one Step
- Every State must be owned by exactly one Agent
- Every State must belong to at least one step
- Every Task must be requestedBy exactly one User
- Every Task must be handledByRun exactly one Run
- Every State must expose all its declared variables via state:hasVariable


# The allowed relation properties are:


## Module `trace` 


### Property `trace:performedBy (Run → Agent)`

- **Meaning**: Indicates which Agent produced or executed the Run
- **Domain**: trace:Run 
- **Range**: trace:Agent  
- **Direction**: from trace:Run to trace:Agent  
- **When to create**: Always create this relation  


## Module `mind` 


### Property `mind:assertedIn (Statement → Step)`

- **Meaning**: Indicates the specific step in which a statement was produced. Only the Step corresponding to the reasoning block 
  from which the Statement was extracted should be linked. 
- **Domain**: mind:Statement - the auditable assertion the auditable assertion extracted from reasoning
- **Range**: trace:Step - the step on which the assertion was generated. The Step node whose id matches the step_id in the reasoning block.
- **Direction**: From mind:Statement to trace:Step 
- **When to Create**: Always for every mind:Statement 

### Property `mind:motivates (Goal → Intention)`

- **Meaning**: Indicates that an Intention exists in order to achieve a specific Goal.
- **Domain**: mind:Goal  
- **Range**: mind:Intention  
- **Direction**: from mind:Goal to mind:Intention  
- **When to create**: Create this relation whenever an Intention is clearly adopted to pursue a Goal.

### Property `mind:expressedIn (Intention → Step)`

- **Meaning**: Anchors an Intention to the Step in which it was formulated or stated. Only the Step corresponding to the reasoning block from which the intention was extracted should be linked.
- **Domain**: `mind:Intention`
- **Range**: `trace:Step`
- **Direction**: from `mind:Intention` to `trace:Step`
- **When to create**: Always create this relation for **every Intention entity**.
  - If a Step contains multiple intentions (e.g., `intention_1`, `intention_2`, …), each intention must have its own `mind:expressedIn` edge pointing to the trace:Step.
  - This ensures that all intentions are properly anchored to the reasoning step they originate from, maintaining accurate traceability in the knowledge graph.

### Property `mind:terminates (TerminationSignal → Step)`

- **Meaning**: Indicates the Step in which the agent explicitly signals termination.
- **Domain**: mind:TerminationSignal  
- **Range**: trace:Step  
- **Direction**: from mind:TerminationSignal to trace:Step  
- **When to create**: Always create this relation for every TerminationSignal.

### Property `mind:goalInStep (Goal → Step)`

- **Meaning**: Links a Goal directly to the Step in which the Goal is expressed or considered relevant.  
- **Domain**: `mind:Goal`  
- **Range**: `trace:Step`  
- **Direction**: from mind:Goal → trace:Step  
- **When to create**:  
  1. Whenever a Goal is extracted from a reasoning block, i.e., from `@start_reasoning(step_id=<STEP_ID>) ... @end_reasoning(step_id=<STEP_ID>)`.  
  2. The corresponding Step is the one whose `@step(id=<STEP_ID>, ...)` matches the `step_id` of the reasoning block from which the Goal was extracted.  
  3. This relation should be created regardless of whether any Intention exists in the reasoning.  

### Property `mind:commitsToToolCall`

- **Domain**: `mind:Intention`
- **Range**: `act:ToolCall`
- **Meaning**: Indicates that an Intention node explicitly commits to the execution
  of a specific ToolCall.
- **When to create**:
  Create this relation if:
    1. A `mind:Intention` is extracted from a reasoning step, AND
    2. The same reasoning step contains the explicit anchor `@call(tool=<TOOL>)`,
       generating an `act:ToolCall`.
- In this case, link:
      mind:Intention  -- mind:commitsToToolCall -->  act:ToolCall
- **Do NOT create**:
  - If the Intention mentions a tool conceptually but no `@call` anchor is present.
  - If a ToolCall exists without a corresponding Intention in the same reasoning step.


## Module `act`


### Property `act:usesTool (ToolCall → Tool)`

- **Meaning**: Identifies the type of tool (`Tool`) actually used by a specific invocation (`ToolCall`). This 
  relation indicates **that each ToolCall is associated with a concrete Tool**, independently of any Intention or reasoning context.  
- **Domain**: `act:ToolCall`  
- **Range**: `act:Tool`  
- **Direction**: from the `ToolCall` node to the `Tool` node  
- **When to create**: For **every ToolCall present in the graph**, automatically create this relation to the corresponding Tool. 
  It does **not require a linked Intention**; the relation is deterministic: if the ToolCall exists, `act:usesTool` exists.  

### Property act:usedInStep (ToolCall → Step)

- **Meaning**: Connects a Tool directly to the Step in which it is used, in addition to being linked via ToolCall.
- **Domain**: act:ToolCall
- **Range**: trace:Step
- **Direction**: from act:Tool to trace:Step
- **When to create**: Create this whenever a ToolCall using this Tool occurs in a Step.


## Module `obs`


### Property `obs:observedIn (Observation → Step)`

- **Meaning**: This relation specifies the exact Step at which the agent first receives
and can access the observation produced by a tool execution.
- **Domain**: obs:Observation
- **Range**: trace:Step
- **Direction**: from the observation to the step in which it became available
- **When to create**: Always create this relation for every Observation. 

### Property `obs:results (act:ToolCall → obs:Observation)`

- **Meaning**: This relation links a ToolCall to the Observation(s) produced
  as a direct result of executing the action, for example as a result of the execution of the tool
- **Domain**: act:ToolCall  
- **Range**: obs:Observation  
- **Direction**: from the act:ToolCall  to the obs:Observation 
- **When to create**: Create this property whenever a tool call returns output,
  regardless of whether the output indicates success, failure, or partial results.


## Module `state` 
  

### Property `state:ownedBy (State → Agent)`

- **Meaning**: Indicates which Agent the State belongs to.
- **Domain**: state:State  
- **Range**: trace:Agent  
- **Direction**: from state:State to trace:Agent  
- **When to create**: Always create this relation for every State.

### Property `state:hasVariable (State → StateVariable)`

- **Meaning**: Links a State to one of its internal variables (represented as entities such as `state:calculator_ready_true`).
- **Domain**: state:State  
- **Range**: state:Calculator_ready  
- **Direction**: from state:State to the corresponding state:Calculator_ready  
- **When to create**: Always create this relation for every variable extracted from a `@state(...)` block.

### Property `state:activeIn (State → Step)`

- **Meaning**: Indicates the Step in which the State snapshot is valid or observed.
- **Domain**: state:State  
- **Range**: trace:Step  
- **Direction**: from state:State to trace:Step  
- **When to create**: For every State entity:
    1. Read current_step_id
    2. Map to Step with matching id
    3. Create: state:State_<id> -- state:activeIn --> trace:Step_<STEP_ID>


## Module `task`


### Property `task:requestedBy (Task → User)`

- **Meaning**: Indicates which User requested the Task.
- **Domain**: task:Task  
- **Range**: trace:User  
- **Direction**: from task:Task to trace:User  
- **When to create**: Always create this relation for every Task, since every Task originates from a User request.

### Property task:handledByRun (Task → Run)

- **Meaning**: Indicates which Run is executing or handling a specific Task.
- **Domain**: task:Task
- **Range**: trace:Run
- **Direction**: from task:Task to trace:Run
- **When to create**: Create this relation whenever a Run is solving or processing a Task.  

# The final instruction is:

- Output only relationship triples (not explanations, not summaries, not free text)
